# DeepSearch PBR/BPS의 정의와 주의점

## 결론

- **정의는 하나뿐이다.** 시장데이터 `BPS` = **연결 지배기업소유주지분 ÷ (보통주+우선주 발행주식수 − 자기주식수)**, `PBR` = 당일 보통주 종가 ÷ BPS. 삼성전자·SK하이닉스·현대차의 FY2024·FY2025, 총 6건 모두 0원 차이로 일치했다.
- **옵션이 없다.** `별도`, `지배주주`, `연결`, `분기`, `보통주` 같은 단어를 붙여도 해석기가 Keyword 등으로 분류하고 무시해 같은 값이 나온다. 다른 정의가 필요하면 `GetFinancialStatements`로 직접 계산해야 한다.
- **직전 사업연도 연말 값을 1년 내내 쓴다.** BPS는 매년 첫 거래일에만 바뀌고 분기 자본은 반영되지 않는다.
- **과거 시계열에는 look-ahead가 있다.** FY N의 BPS·EPS가 N+1년 첫 거래일(예: 2026-01-02)부터 붙어 있다. 이 날짜에는 아직 FY N 결산이 공시되지 않았으므로 백테스트에 그대로 쓰면 안 된다.

검증일 2026-11-20 · 대상: compute 자연어 쿼리(`PBR`, `BPS`, `EPS`, `PER`), `GetFinancialStatements`, `GetCompanyDividends`, `SearchFirmFundamentalsForecasts` · 재현 스크립트: [verify_pbr_bps.py](verify_pbr_bps.py)

## 질문

PBR은 계산 방법에 따라 값이 크게 달라진다. 순자산을 지배주주지분으로 볼지 비지배지분까지 포함한 자본총계로 볼지, 연결인지 별도인지, 주식수를 발행주식수로 쓸지 자사주를 뺀 유통주식수로 쓸지, 우선주를 넣을지, 연말 기준인지 최근 분기 기준인지가 모두 변수다.

1. DeepSearch에서 이런 정의를 옵션으로 고를 수 있는가?
2. 기본 `PBR`/`BPS`는 어떤 정의이고, 언제 갱신되는가?

## 방법

1. **키워드 옵션 테스트.** `삼성전자 PBR` 앞뒤에 정의를 바꿀 만한 단어를 붙여 호출하고, 해석 결과(`interpretation.tagged`)와 값을 비교했다.
2. **갱신 시점.** `{기업} 종가 PBR BPS EPS PER 2023-01-01-2026-11-20` 일별 시계열에서 BPS나 EPS가 바뀐 날만 추렸다.
3. **정의 역산.** `GetFinancialStatements`에서 FY2024·FY2025 연결·별도 계정을 받아 정의 5가지로 BPS를 계산하고, 해당 회계연도 다음 해 첫 거래일의 시장데이터 BPS와 비교했다. 대상은 삼성전자(우선주 1종), SK하이닉스(우선주 없음), 현대차(우선주 3종)다.
4. **다른 경로.** `GetCompanyDividends`의 `주당순자산(원)`과 컨센서스(`SearchFirmFundamentalsForecasts`)의 `csd_bps`를 확인했다.

계산에 쓴 계정 (`GetFinancialStatements`, `report_type="IFRS"`, `is_annual=True`):

| 항목 | report_id | account_id | name_ko |
|---|---|---|---|
| 지배주주지분 | 11 | 8050 | 지배기업소유주지분 |
| 자본총계 | 11 | 8900 | 자본총계 |
| 보통주 발행주식수 | 11 | 8111 | [보통주발행주식수] |
| 우선주 발행주식수 | 11 | 8121 | [우선주발행주식수] (현대차는 1·2·3우선주 합계로 보인다. 이 값으로 BPS가 정확히 맞음) |
| 보통주 자기주식수 | 11 | 8431 | [보통주자기주식수] |
| 우선주 자기주식수 | 11 | 8432 | [우선주자기주식수] |
| 기본주당이익 | 12 | 9009 | 기본주당이익 |

## 결과

### 1. 키워드는 무시된다

| 쿼리 | 해석 | 값 |
|---|---|---|
| `삼성전자 PBR` | Entity + Property | 2.86 |
| `삼성전자 별도 PBR` | `별도` → Keyword | 2.86 |
| `삼성전자 지배주주 PBR` | `지배주주` → Keyword | 2.86 |
| `삼성전자 BPS` | Entity + Property | 63,997 |
| `삼성전자 연결 BPS` | `연결` → **Entity**로 오인 | 63,997 |
| `삼성전자 분기 BPS` | `분기` → Keyword | 63,997 |
| `삼성전자 보통주 BPS` | `보통주` → Keyword | 63,997 |
| `삼성전자 주당순자산가치` | Property (BPS 동의어) | 63,997 |

재무제표 쿼리에서는 `별도`, `분기`, `누적`이 옵션으로 동작한다([1_기본적인_데이터_조회방법.md](../../docs/reference/1_기본적인_데이터_조회방법.md) "분기재무제표 쿼리"). 시장데이터 배수 지표에는 그런 옵션이 없다. 원자료: [data/keyword_variants.csv](data/keyword_variants.csv)

### 2. 정의 역산: 연결 지배지분 ÷ 유통주식수와 정확히 일치

FY2025 기준이다. 시장데이터 BPS는 2026-01-02부터 적용된 값이고, PBR은 2026-11-20 종가(삼성전자 183,100원, SK하이닉스 1,113,000원, 현대차 255,000원)로 계산했다.

| 정의 | 삼성전자 BPS (PBR) | SK하이닉스 BPS (PBR) | 현대차 BPS (PBR) |
|---|---|---|---|
| **연결 지배지분 / 유통주식수 (= DeepSearch 값)** | **63,997 (2.86)** | **171,751 (6.48)** | **439,541 (0.58)** |
| 연결 지배지분 / 발행주식수(자사주 포함) | 62,995 (2.91) | 165,544 (6.72) | 435,007 (0.59) |
| 연결 자본총계(비지배 포함) / 유통주식수 | 65,808 (2.78) | 171,966 (6.47) | 485,997 (0.52) |
| 별도 자본총계 / 유통주식수 | 38,359 (4.77) | 167,194 (6.66) | 266,392 (0.96) |
| 연결 지배지분 / 보통주 유통주식수만 | 72,808 (2.51) | 171,751 (6.48) | 568,396 (0.45) |

- 6건(3개사 × FY2024·FY2025) 모두 첫 번째 정의와 차이가 0원이었다. 예를 들어 삼성전자 FY2025는 424.31조원 ÷ (6,735,612,586 − 105,432,448)주 = 63,997원이다.
- SK하이닉스는 우선주가 없어서 첫째와 다섯째 정의의 값이 같다. 우선주 포함 여부는 삼성전자(+8,811원 차이)와 현대차(+128,855원 차이)가 구분해 준다.
- 정의를 무엇으로 잡느냐에 따라 PBR이 크게 달라진다. 지주·자회사 구조가 큰 회사일수록 별도와 연결의 차이가 크다(현대차 0.58 대 0.96).

원자료: [data/bps_definition_check.csv](data/bps_definition_check.csv) (FY2024 포함 전체)

### 3. 갱신 시점: 매년 첫 거래일, 그리고 소급 적용

삼성전자에서 BPS·EPS가 바뀐 날만 뽑은 것이다.

| 날짜 | 종가 | BPS | EPS | PBR | 적용된 결산 |
|---|---|---|---|---|---|
| 2022-12-29 | 55,300 | 43,611 | 5,777 | 1.27 | FY2021 |
| 2023-01-02 | 55,500 | 50,817 | 8,057 | 1.09 | FY2022 |
| 2024-01-02 | 79,600 | 52,002 | 2,131 | 1.53 | FY2023 |
| 2025-01-02 | 53,400 | 57,951 | 4,950 | 0.92 | FY2024 |
| 2026-01-02 | 128,500 | 63,997 | 6,571 | 2.01 | FY2025 |
| 2026-05-29 | 317,000 | 63,997 | **6,605** | 4.95 | FY2025 EPS 교체 |

SK하이닉스와 현대차도 같은 패턴이다(첫 거래일 교체, 2026-05-29에 EPS만 교체). 원자료: [data/bps_eps_changepoints.csv](data/bps_eps_changepoints.csv)

### 4. 다른 경로

- **`GetCompanyDividends`의 `주당순자산(원)`은 쓰지 말 것.** 삼성전자 FY2025 값 36,091원은 위 다섯 정의 어느 것과도 맞지 않는다(별도 자본총계 / 유통주식수로 계산해도 38,359원). 1분기·3분기 값은 0인 경우가 많다. 반면 같은 표의 `주당순이익(원)`은 공시된 연결 기본주당이익(FY2025 6,605원)과 같다. 원자료: [data/dividends_bps.csv](data/dividends_bps.csv)
- **추정 BPS·PBR은 컨센서스에 있다.** `SearchFirmFundamentalsForecasts(삼성전자, True, "K", 2026-05-20)`의 `csd_bps`, `csd_pbr`가 증권사별 연결 기준 추정치다. 예를 들어 2026E BPS는 100,457~114,467원, PBR은 2.1~2.6배다. `csd_` 없는 `bps`, `pbr`(개별 기준)은 비어 있었다. 원자료: [data/consensus_bps.csv](data/consensus_bps.csv)

## 실무 영향

- **스크리닝·현재값 비교:** 기본 `PBR`을 그대로 써도 된다. 다만 정의가 "직전 연말 연결 지배지분"이라는 점은 밝혀 두는 게 좋다. 2026년 11월에도 FY2025 말 자본을 쓰므로, 3분기까지 자본이 크게 늘거나 준 회사는 실제 PBR과 차이가 난다.
- **백테스트:** 시계열을 그대로 쓰면 look-ahead가 생긴다. 2026-01-02에 이미 FY2025 BPS가 적용돼 있는데, 1월 첫 거래일에는 전년도 말 연결 자본을 공시한 12월 결산법인이 없다(연간 실적 발표는 보통 1월 말 이후, 확정치는 3월 사업보고서). 시점 정합성이 필요하면 `GetFinancialStatements` 값을 공시일 이후에만 쓰도록 직접 붙여야 한다. 재무제표 재작성 문제는 [../restatement/](../restatement/) 참고.
- **다른 정의가 필요할 때:** 위 계정표의 id로 분자와 분모를 골라 직접 계산한다. 최근 분기 기준이 필요하면 `is_annual=False`로 분기 재무상태표를 받는다.
- **다른 출처와 비교할 때:** 출처마다 정의(발행주식수 대 유통주식수, 우선주 포함 여부, 기준 시점)가 다를 수 있다. 값이 다르면 위 표의 정의별 값과 먼저 맞춰 본다. 다른 출처의 정의는 이번에 확인하지 않았다.

## 한계 / 미확인

- 검증한 표본은 대형 제조업 3개사다. 금융업(은행·보험)이나 지배지분 계정이 없는 회사, 자본잠식 회사, 12월 결산이 아닌 회사는 확인하지 않았다.
- `is_annual=False`로 분기 BPS를 직접 계산하는 방법은 계정이 있다는 것만 알고 값은 검증하지 않았다.
- **EPS는 BPS보다 정의가 불안정하다.** FY2025 EPS는 2026-05-29부터 공시된 기본주당이익(삼성전자 6,605원, SK하이닉스 62,044원, 현대차 36,088원)으로 바뀌었지만, 그 전에는 다른 값(6,571원, 58,955원, 35,392원)이었다. FY2024 EPS는 삼성전자만 공시값(4,950원)과 같고, SK하이닉스(시장데이터 27,182원, 공시 28,732원)와 현대차(46,151원, 47,615원)는 1년 내내 달랐다. 공시값이 아닌 쪽의 정의는 확인하지 못했다. PER 정의는 별도 주제로 검증할 필요가 있다.
- 과거 시계열이 언제 채워졌는지(실시간이었는지 나중에 소급했는지)는 API로 알 수 없다. 확인할 수 있는 것은 현재 저장된 값이 첫 거래일에 붙어 있다는 사실뿐이다.
- `GetCompanyDividends`의 `주당순자산(원)` 정의는 끝내 확인하지 못했다.

## 재현 방법

```bash
# 레포 루트 .env 에 API_KEY (DeepSearch) 필요. 키는 출력·캐시에 남지 않음
python research/pbr_bps/verify_pbr_bps.py            # 기준일 2026-11-20
python research/pbr_bps/verify_pbr_bps.py 2026-12-31 # 기준일 변경
```

- API 호출은 25회다(키워드 8, 시계열 3, 재무제표 12, 배당 1, 컨센서스 1). 원시 응답은 `data/cache/`(git 제외)에 쿼리 해시로 저장되고, 다시 실행하면 캐시를 쓴다. 최신 값으로 다시 받으려면 캐시를 지우면 된다.
- 결과 CSV 5개가 `data/`에 생성된다(UTF-8 BOM, 엑셀에서 바로 열림). **DeepSearch 원시 값이라 공개 저장소에는 올리지 않는다**(`.gitignore`). 본문의 "원자료" 링크는 스크립트를 실행한 뒤 로컬에서 열린다. 본문 표에는 검증에 필요한 대표값만 옮겼다.
