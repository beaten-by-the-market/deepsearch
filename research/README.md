# research — DeepSearch 데이터 검증 노트

DeepSearch API 값이 **정확히 무엇인지**(정의·기준 시점·재작성 반영 여부)를 실제 호출과 원천 공시로 대조해 기록한다.
DeepSearch 데이터로 분석·백테스트를 하기 전에 해당 항목을 먼저 확인한다.

| 주제 | 한 줄 결론 | 검증일 |
|---|---|---|
| [restatement/](restatement/) | `GetFinancialStatements`의 과거 연도 값은 **원래 공시값도, 재작성값도 일관되게 보장하지 않는다.** 재작성된 회사·연도의 약 3/4은 다음 해 보고서의 재작성값, 1/4은 원래값이다. 손익만 바뀐 재분류는 대부분 재작성값이고, 재무상태표까지 바뀐 소급 재작성은 갈린다. IFRS17 보험사 2022년은 대부분 재작성 전 값이다. | 2026-11-20 |
| [pbr_bps/](pbr_bps/) | 시장데이터 BPS는 '연결 지배지분 ÷ 유통주식수(보통+우선−자사주), 직전 연말' 한 가지 정의뿐이고 옵션 키워드는 무시된다. 과거 시계열은 FY N 값이 N+1년 첫 거래일부터 붙어 있어 look-ahead가 있다. | 2026-11-20 |

## 폴더 규칙

```
research/<주제>/
  README.md      본문 (관리 대상 문서)
  *.py           재현 스크립트 (폴더 바로 아래)
  data/          커밋하는 작은 결과물 (CSV, 요약 md)
  data/cache/    원시 API 응답 캐시 (git 제외)
```

README 형식: 제목 → **결론**(3~5줄) → 메타 줄(검증일 · 대상 API/함수 · 재현 스크립트) → 질문 → 방법 → 결과 → 실무 영향 → 한계/미확인 → 재현 방법 → 변경 이력.
숫자에는 단위를, 주장에는 근거(호출식·공시·링크)를 붙인다. API 키 값은 문서·로그에 남기지 않는다(DeepSearch는 레포 루트 `.env`의 `API_KEY`).
