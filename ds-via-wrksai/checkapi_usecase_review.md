# 체크API 케이스 시나리오 → 웍스 DeepSearch 도구로 구현 가능성 검토

> 검토일 2026-10-22. **실행하지 않고 문서만 보고 판단했다.**
> - 대상: `check-api-krx-dl/케이스시나리오/` 6개 분류, 42개 시나리오 (KOSCOM CHECK API 기반)
> - 기준: 웍스AI `dsrch_*` 도구 테스트 결과 ([TOOLS.md](TOOLS.md))
>
> 판정 기호
> - ◎ 거의 그대로 구현 가능
> - ○ 핵심 일부만 가능 (빠지는 데이터를 비고에 적음)
> - ✕ 핵심 데이터가 없어 불가

## 결론

| 판정 | 개수 |
|---|---|
| ◎ 거의 그대로 | 3 |
| ○ 일부 가능 | 15 |
| ✕ 불가 | 24 |

- **DeepSearch는 CHECK의 대체재가 아니라 보완재다.** CHECK 시나리오의 뼈대인 **시세 순위·투자자 수급·공매도·대차·신용·파생·호가·틱·NXT** 데이터가 dsrch 도구에는 하나도 없다.
- 반대로 **뉴스는 DeepSearch가 더 낫다.** CHECK 뉴스에는 종목 태그가 없어 "종목별로 직접 찾아야" 하지만, DeepSearch는 기사마다 관련 기업이 붙어 있고 리포트·IR·AI 브리핑도 있다.
- 구현 가치가 있는 영역은 **펀더멘털(재무·밸류에이션·배당)**과 **공시·뉴스 타임라인**이다.

## DeepSearch로 오히려 확장되는 것

CHECK 시나리오에 없지만 dsrch로 새로 만들 수 있는 케이스:

- **종목 태그 뉴스 + AI 브리핑**: "오늘 이 종목 왜 올랐어?"에 get_stock_briefing이 등락 원인 요약과 관련 기사를 바로 준다. 시나리오 3-01을 보강할 수 있다.
- **증권사 리포트 검색 (research_insight)**: 컨센서스 숫자는 없지만, 리포트 제목·요약으로 "최근 눈높이가 올라가는 중인지"를 정성적으로 볼 수 있다. 1-02·1-08의 약한 대체다.
- **해외 뉴스·어닝콜·ETF 구성**: 해외 피어 비교, ETF 편입 종목 분석.
- **테마별 종목 (get_invest_tag_stocks)**: "AI 테마 종목 목록" → 3번 스크리너의 출발점으로 쓸 수 있다.

## 구현할 때 주의할 점

1. **비용**: 웍스는 도구 호출 수만큼 사용량이 든다(테스트에서 묶음당 7~12%). 종목을 여러 개 도는 시나리오(피어 비교, 배당주 비교)는 종목 수를 5개 안팎으로 제한해야 한다.
2. **실행 환경**: CHECK 시나리오는 Claude Code + 파이썬 스크립트로 돌지만, dsrch는 **웍스 에이전트 채팅으로만** 쓸 수 있다. 결과를 파일로 쌓거나 매일 자동 실행하려면 웍스의 워크플로우·대화 예약 기능을 써야 한다.
3. **확인이 필요한 미검증 항목** (구현 전 1회씩 확인 권장):
   - get_market_indices 85개 지수에 KRX 섹터지수·환율이 포함되는지 → 4-01, 4-04
   - 뉴스 응답(detail_level=full)에 감성(polarity) 필드가 있는지 → 2-06
   - DART 공시 검색에 "조회공시 답변"이 잡히는지 → 2-07
   - 공시 content_url 본문을 웍스에서 읽을 수 있는지 → 1-05, 2-05

## 추천 순서

먼저 구현해 볼 만한 것 (◎ + 가치 높은 ○):

1. **1-07 재무 트렌드**, **1-04 피어 밸류에이션**, **1-10 배당주**: 도구가 안정적으로 동작하고 결과가 바로 쓸모 있다.
2. **2-07 뉴스·공시 결합 타임라인**: DeepSearch 뉴스의 종목 태그 장점이 가장 잘 살아난다. KRX 조회공시 업무와도 직결된다.
3. **3-01 오늘 급등락**의 변형: trending_companies + stock_briefing + 공시 검색.

CHECK에 맡겨야 하는 것: 수급·공매도·대차·신용·시장경보·파생·금리·호가·NXT 관련 전부(24개 중 대부분).
